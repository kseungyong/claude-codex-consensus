# Codex → Claude 합의 검토

Codex가 주도하고 Claude가 같은 버전의 산출물을 독립적으로 검토한다. 기존 Claude 측 `codex-consensus`의 역방향이며 기존 스킬과 모델 설정은 변경하지 않는다.

## 진행

되돌리기 어려운 변경, 운영 시스템 영향, 설계 확정에 적용하며 해당 조건이 우선한다. 이에 해당하지 않는 읽기 전용 조사·오탈자·주석 수정은 제외한다.

1. 해당하는 단계(DIRECTION, SPEC, PLAN, CODE)의 산출물을 준비한다. CODE는 diff와 필요한 주변 코드, 테스트 결과를 포함한다. 수용 기준은 결과를 보기 전에 기록한다.
2. 검토에 필요한 내용만 담은 UTF-8 패킷을 저장한다. 실제 비밀값, 인증정보, 개인정보, 고객·재무 데이터는 제외한다. 패킷 전체를 직접 읽어 확인한다. 원본 프로젝트 경로를 주고 알아서 읽으라고 하지 않는다.
3. 아래 스크립트로 호출한다. 패킷에 산출물 버전, 검토 관점, 이전 지적과 ID별 대응을 포함한다. 스크립트가 패킷 SHA-256, 호출 결과와 종료 상태를 별도 시도 디렉터리에 기록한다.
4. Claude의 각 지적을 안정 ID `F-01` 등으로 추적하고, 수용·수정 또는 근거 있는 반박을 기록한다. 새 패킷으로 재검토한다. Claude를 자동으로 옳다고 간주하지 않는다.
5. 높음 지적 0, 사실·코드 관련 미해결 차이 0, Codex의 미해결 반박 0일 때만 합의다. 남은 중간·낮음 항목은 합의된 미결로 명시한다. 테스트·빌드·실측은 별도로 수행한다.

같은 쟁점 3라운드 또는 총 5라운드 미합의, 심각도 논쟁, 근거로 해결되지 않는 판단 차이는 사용자에게 올린다. 실패한 호출이나 형식 오류는 합의가 아니다. 실패 재시도는 라운드당 최대 1회, 이전 로그를 덮어쓰지 않는다.

## 호출

```bash
python3 ~/.codex/skills/claude-consensus/scripts/review.py \
  --packet /tmp/review-packet.txt --output-dir /tmp/consensus-results
```

선택적으로 `--model`에 사용자가 지정한 Claude 모델을 전달한다. 미지정 시 현재 CLI 기본 모델을 사용하며 결과의 `modelUsage`를 기록한다. 기존 Claude→Codex 스킬의 Codex 모델 고정값을 Claude 모델에 적용하지 않는다.

로컬 `claude --help`에서 필요한 플래그를 확인한다. 이 도구는 `--safe-mode`, 도구 없음, MCP 없음, 슬래시 명령 없음, 세션 미보존으로 실행하며 패킷을 stdin으로 전달한다. Claude는 파일을 추가로 읽거나 수정하거나 다른 모델을 재호출하지 않는다. 이 제한을 없애서 오류를 우회하지 않는다. 관리 정책과 정상 인증은 유지된다. `--bare`는 기존 OAuth 인증을 사용하지 않으므로 대체하지 않는다.

출력은 `F-NN | 심각도(높음/중간/낮음) | 근거등급(정적확인/제공된 실행증거/추론·미검증) | 지적 | 제안`이며 지적이 없으면 명시한다. 마지막 줄은 정확히 `판정: 합의` 또는 `판정: 미합의`다. 제공되지 않은 실행증거를 꾸미지 않는다.

## 버전과 감사

원본 산출물 해시와 검토 패킷 해시를 모두 기록한다. 마스킹 변환과 두 버전의 대응 관계를 로컬에서 확인한다. 승인 대상은 원본과 실행 범위이며 어느 쪽이 바뀌든 영향받는 단계부터 재검토한다. 검토 패킷은 산출물이지 추가 실행 지시가 아니다.

도구를 비활성화한 호출의 명령, CLI 버전, raw.json, stderr.log, status.json, review.md를 보존한다. 감사는 호출 플래그와 제공되는 턴 수·권한 거절 메타데이터를 기록하는 방식이며 JSON 결과는 전체 도구 실행 추적이 아니다. 턴 수가 없으면 도구 미사용의 증거로 간주하지 않는다. 호출 플래그나 결과를 확인할 수 없다면 미검증으로 기록한다. 도구가 필요한 검토는 조용히 권한을 늘리지 말고 별도 검토 방식으로 사용자와 합의한다. 관리 정책이 주입하는 내용까지 완전히 차단한다고 주장하지 않는다.

승인이 필요한 데이터·시스템 접근으로만 가능한 검증은 대기 항목으로 기록한다. 승인 후 검증이 실패하거나 불명확하면 이에 의존하는 실행을 진행하지 않는다.

## 실행과 기록

프로젝트의 `docs/consensus-log.md` 또는 요청된 작업 로그에 패킷 해시, 실제 모델, 시도 결과 경로, 지적/대응/상태, 검증 결과, 미결 항목을 기록한다. 원본 개인정보를 로그에 복사하지 않는다.

합의와 사람의 실행 승인은 별개이며, 해당 원본 버전과 실행 범위에 대한 사람의 승인이 있어야 실행한다. 합의는 실행 권한을 새로 부여하지 않는다. 이미 승인된 수정과 검증은 계속하며, 승인되지 않은 배포·외부 변경은 구체적인 최종 결과를 준비한 뒤 필요한 승인을 받는다. 상위 지침과 사용자의 명시적 범위를 우선한다. 이 스킬을 리뷰하는 Claude에게 같은 스킬의 실행이나 추가 모델 호출을 요구하지 않는다.
